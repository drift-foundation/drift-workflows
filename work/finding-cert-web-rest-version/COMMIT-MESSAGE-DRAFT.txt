adopt web-rest 0.7 (0.6.5 -> 0.7.0): unblock cert source-rebuild; uflowsd 0.8.1; reseal

Certification stage_packages failed for uflowsd: the web-rest 0.6 constraint
became unsatisfiable once drift-web 558b647 bumped the package to 0.7.0. The
cert lane resolves deps via `drift lock emit --source-rebuild` against drift-web
SOURCE, which now produces only 0.7.0, so a 0.6 range has no candidate. Not a
defect on either side — the intended consequence of a deliberate producer bump
meeting a pinned consumer constraint, and per AGENTS.md's current-main rule it
is immediate integration work. Adopted in this cert train rather than waiting
for web-rest 0.7.0 to certify: the same combined run stages web-rest before
drift-workflows, so waiting would deadlock it.

Source migration for web-rest 0.7: none required. web-rest 0.7.0's two
breaking changes are with_response_header returning core.Result<Void,
HeaderError> and RestError gaining a required defaultless headers_json field.
Neither intersects this repo's web.rest surface — 16 symbols across
runner.drift and participant-stub app.drift, with zero with_response_header
calls and zero RestError constructions tree-wide. json_response, the only
response constructor used here, keeps its signature verbatim. The single
source edit in the whole change is RUNNER_VERSION, which the artifact bump
requires and 0.7.0 does not. The 0.7.0 response-framing fix (server-owned
close; one Connection decision folded through DispatchOut) is inherited, not
reimplemented.

artifact source content identity, so the sealed 0.8.0 cannot be reissued with
different manifest content; patch class is correct because no workflows-owned
contract changed. RUNNER_VERSION synced (it backs --version for both mfrunner
and uflowsd). singular 0.10.0 and microflows 0.9.0 are untouched — neither
depends on web-rest.
